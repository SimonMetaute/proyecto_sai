# Global Exception Handler Specification - NexusMarket

## 1. Purpose

This document defines the single error-handling contract for the REST delivery layer. It applies to every endpoint and middleware error, regardless of whether the detected stack is TypeScript/Express, TypeScript/NestJS, or Java/Spring Boot.

The domain remains technology independent. Domain exceptions are declared in `domain/exceptions/`; the REST/infrastructure layer translates them into HTTP responses.

---

## 2. Responsibilities

The global handler must:

1. Capture errors from controllers, routes, authentication middleware, authorization middleware, validation, persistence adapters and unexpected runtime failures.
2. Map known exceptions deterministically to an HTTP status.
3. Return one stable error response shape.
4. Avoid exposing stack traces, SQL details, secrets or internal implementation data in production responses.
5. Log unexpected errors with a correlation/request identifier.
6. Preserve the original exception for diagnostics and tests.
7. Respect `res.headersSent` or the equivalent framework rule and delegate safely when a response has already started.

No controller should duplicate the complete exception-to-HTTP mapping. Local catches are allowed only to add context or to rethrow into the global handler.

---

## 3. Standard Error Response

All handled errors must use this shape, unless the API contract explicitly requires another representation:

```json
{
  "timestamp": "2026-09-23T12:00:00.000Z",
  "status": 404,
  "code": "PRODUCT_NOT_FOUND",
  "message": "Product not found",
  "path": "/api/v1/seller/products/prod-999",
  "requestId": "req-01H...",
  "details": null
}
```

### Rules:

- `timestamp` is generated by the handler (ISO 8601 format).
- `status` is the HTTP status actually returned.
- `code` is stable and machine-readable; clients must not parse `message`.
- `message` is safe for the client; never expose internal implementation details.
- `path` identifies the request path without query secrets.
- `requestId` correlates the response with server logs for debugging.
- `details` contains safe validation details (e.g., which fields failed) or is `null`.
- Unexpected errors use a generic message such as `Internal server error`.

---

## 4. Exception Classification

The mapping must be explicit and covered by tests:

| Exception Category | HTTP Status | Example Codes | Domain Examples |
|---|---:|---|---|
| Malformed JSON, missing/invalid request data | 400 | `INVALID_REQUEST`, `MALFORMED_JSON` | Empty email, invalid phone number |
| Domain validation or semantic validation failure | 400 by default; 422 only when explicitly declared by an endpoint contract | `INVALID_DOMAIN_VALUE` | Insufficient inventory for publication, invalid tax jurisdiction |
| Missing or invalid credentials/token | 401 | `AUTHENTICATION_REQUIRED`, `INVALID_CREDENTIALS`, `TOKEN_EXPIRED` | Missing JWT, expired token, wrong password |
| Authenticated user without permission | 403 | `FORBIDDEN`, `INSUFFICIENT_ROLE` | Buyer trying to approve seller, Seller accessing Admin endpoint |
| Resource does not exist | 404 | `PRODUCT_NOT_FOUND`, `ORDER_NOT_FOUND`, `SELLER_NOT_FOUND` | Order ID doesn't exist, product deleted |
| Duplicate resource or state conflict | 409 | `RESOURCE_ALREADY_EXISTS`, `INVALID_STATE_TRANSITION`, `SELLER_ALREADY_VERIFIED` | Email already registered, product already published, order already delivered |
| Persistence/service dependency unavailable | 503 | `DEPENDENCY_UNAVAILABLE`, `DATABASE_ERROR` | Database down, external payment gateway unreachable |
| Unexpected programming/runtime error | 500 | `INTERNAL_ERROR` | Null pointer, uncaught exception in domain service |

### Rules:

- The implementation must not use a broad fallback that maps every unknown error to `400`.
- Unknown errors are server errors and must map to `500`.
- `422` is used only when the endpoint documentation explicitly declares it.
- `400` is the default for domain validation failures unless otherwise specified.
- All exception mappings must be centralized and tested.

## 5. Domain Exception Contract

Each domain exception must have:

1. A stable exception class (e.g., `ProductNotPublishedException`, `InsufficientInventoryException`).
2. A stable external error code (e.g., `PRODUCT_NOT_PUBLISHED`, `INSUFFICIENT_INVENTORY`).
3. A safe default message (never expose SQL, stack traces, or secrets).
4. An explicit classification (400, 401, 403, 404, 409, 503, 500) or a central registry entry.
5. No dependency on Express, Spring, HTTP, ORM or database classes.

**Example Domain Exception:**

```java
public class ProductNotPublishedException extends DomainException {
    private String productId;
    
    public ProductNotPublishedException(String productId, String reason) {
        super("PRODUCT_NOT_PUBLISHED", 
              "Product cannot be published: " + reason);
        this.productId = productId;
    }
    
    public String getProductId() { return productId; }
    
    @Override
    public int getHttpStatus() { return 422; } // Unprocessable Entity
}
```

## 7. Framework Implementations

### 7.1 TypeScript / Express

Implement an Express error middleware with the signature:

```typescript
(error: unknown, req: Request, res: Response, next: NextFunction) => void
```

**Requirements:**

- Register it **after all routes** and ordinary middleware.
- Use `next` when headers have already been sent.
- Handle rejected async handlers through the framework-compatible wrapper or explicit propagation.
- Assign or reuse a request ID (e.g., from `X-Request-ID` header or generate a UUID).
- Never send two responses for one request.
- Return the standard error response.
- Log stack traces only on the server side (never in response body).

**Example Implementation:**

```typescript
// src/infrastructure/middleware/GlobalExceptionHandler.ts
import { Request, Response, NextFunction } from 'express';
import { v4 as uuidv4 } from 'uuid';

export class GlobalExceptionHandler {
  static handle(error: unknown, req: Request, res: Response, next: NextFunction): void {
    // Prevent double response
    if (res.headersSent) {
      return next(error);
    }

    const requestId = req.id || uuidv4();
    const timestamp = new Date().toISOString();
    const path = req.originalUrl;

    let statusCode = 500;
    let code = 'INTERNAL_ERROR';
    let message = 'An unexpected error occurred';
    let details = null;

    if (error instanceof SyntaxError && 'body' in error) {
      // Malformed JSON
      statusCode = 400;
      code = 'MALFORMED_JSON';
      message = 'Request body is not valid JSON';
    } else if (error instanceof ValidationError) {
      // DTO validation failure
      statusCode = 400;
      code = 'INVALID_REQUEST';
      message = error.message;
      details = error.errors;
    } else if (error instanceof DomainException) {
      // Domain exception
      statusCode = error.getHttpStatus ? error.getHttpStatus() : 400;
      code = error.code || 'DOMAIN_ERROR';
      message = error.message;
    } else if (error instanceof AuthenticationError) {
      statusCode = 401;
      code = 'AUTHENTICATION_REQUIRED';
      message = error.message;
    } else if (error instanceof ForbiddenError) {
      statusCode = 403;
      code = 'FORBIDDEN';
      message = error.message;
    } else if (error instanceof NotFoundError) {
      statusCode = 404;
      code = 'RESOURCE_NOT_FOUND';
      message = error.message;
    } else if (error instanceof ConflictError) {
      statusCode = 409;
      code = error.code || 'RESOURCE_ALREADY_EXISTS';
      message = error.message;
    } else if (error instanceof ServiceUnavailableError) {
      statusCode = 503;
      code = 'DEPENDENCY_UNAVAILABLE';
      message = 'Service temporarily unavailable';
    }

    // Log error (server-side only)
    console.error(`[${requestId}] ${statusCode} ${code}:`, error);

    // Send response
    res.status(statusCode).json({
      timestamp,
      status: statusCode,
      code,
      message,
      path,
      requestId,
      details,
    });
  }
}

// In main app.ts or server setup:
// app.use(GlobalExceptionHandler.handle);
```

### 7.2 TypeScript / NestJS

Implement a global exception filter:

```typescript
// src/infrastructure/filters/GlobalExceptionFilter.ts
import {
  ExceptionFilter,
  Catch,
  ArgumentsHost,
  HttpStatus,
  Logger,
} from '@nestjs/common';
import { Response } from 'express';
import { v4 as uuidv4 } from 'uuid';

@Catch()
export class GlobalExceptionFilter implements ExceptionFilter {
  private readonly logger = new Logger(GlobalExceptionFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest();

    const requestId = request.id || uuidv4();
    const timestamp = new Date().toISOString();
    const path = request.originalUrl;

    let statusCode = HttpStatus.INTERNAL_SERVER_ERROR;
    let code = 'INTERNAL_ERROR';
    let message = 'An unexpected error occurred';
    let details = null;

    if (exception instanceof DomainException) {
      statusCode = exception.getHttpStatus?.() ?? HttpStatus.BAD_REQUEST;
      code = exception.code;
      message = exception.message;
    } else if (exception instanceof AuthenticationError) {
      statusCode = HttpStatus.UNAUTHORIZED;
      code = 'AUTHENTICATION_REQUIRED';
      message = exception.message;
    } else if (exception instanceof ForbiddenException) {
      statusCode = HttpStatus.FORBIDDEN;
      code = 'FORBIDDEN';
      message = exception.message;
    } else if (exception instanceof NotFoundException) {
      statusCode = HttpStatus.NOT_FOUND;
      code = 'RESOURCE_NOT_FOUND';
      message = exception.message;
    } else if (exception instanceof ConflictException) {
      statusCode = HttpStatus.CONFLICT;
      code = exception.code || 'RESOURCE_ALREADY_EXISTS';
      message = exception.message;
    }

    this.logger.error(
      `[${requestId}] ${statusCode} ${code}: ${message}`,
      exception instanceof Error ? exception.stack : exception,
    );

    response.status(statusCode).json({
      timestamp,
      status: statusCode,
      code,
      message,
      path,
      requestId,
      details,
    });
  }
}

// In main.ts:
// app.useGlobalFilters(new GlobalExceptionFilter());
```

### 7.3 Java / Spring Boot

Implement a global `@RestControllerAdvice`:

```java
// com.nexusmarket.infrastructure.rest.GlobalExceptionHandler
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.context.request.WebRequest;
import org.springframework.web.servlet.mvc.method.annotation.ResponseEntityExceptionHandler;
import java.time.Instant;
import java.util.UUID;

@RestControllerAdvice
public class GlobalExceptionHandler extends ResponseEntityExceptionHandler {

    @ExceptionHandler(DomainException.class)
    public ResponseEntity<ErrorResponse> handleDomainException(
            DomainException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(ex.getHttpStatus())
                .code(ex.getCode())
                .message(ex.getMessage())
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.valueOf(ex.getHttpStatus()));
    }

    @ExceptionHandler(AuthenticationException.class)
    public ResponseEntity<ErrorResponse> handleAuthenticationException(
            AuthenticationException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(401)
                .code("AUTHENTICATION_REQUIRED")
                .message(ex.getMessage())
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.UNAUTHORIZED);
    }

    @ExceptionHandler(ForbiddenException.class)
    public ResponseEntity<ErrorResponse> handleForbiddenException(
            ForbiddenException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(403)
                .code("FORBIDDEN")
                .message(ex.getMessage())
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.FORBIDDEN);
    }

    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleResourceNotFoundException(
            ResourceNotFoundException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(404)
                .code("RESOURCE_NOT_FOUND")
                .message(ex.getMessage())
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.NOT_FOUND);
    }

    @ExceptionHandler(ConflictException.class)
    public ResponseEntity<ErrorResponse> handleConflictException(
            ConflictException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(409)
                .code(ex.getCode())
                .message(ex.getMessage())
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.CONFLICT);
    }

    @ExceptionHandler(ServiceUnavailableException.class)
    public ResponseEntity<ErrorResponse> handleServiceUnavailableException(
            ServiceUnavailableException ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(503)
                .code("DEPENDENCY_UNAVAILABLE")
                .message("Service temporarily unavailable")
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.SERVICE_UNAVAILABLE);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(
            Exception ex,
            WebRequest request) {
        
        String requestId = extractRequestId(request);
        
        // Log the full stack trace server-side
        logger.error("[" + requestId + "] Unexpected error", ex);
        
        ErrorResponse errorResponse = ErrorResponse.builder()
                .timestamp(Instant.now().toString())
                .status(500)
                .code("INTERNAL_ERROR")
                .message("An unexpected error occurred")
                .path(request.getDescription(false).replace("uri=", ""))
                .requestId(requestId)
                .details(null)
                .build();
        
        return new ResponseEntity<>(errorResponse, HttpStatus.INTERNAL_SERVER_ERROR);
    }

    private String extractRequestId(WebRequest request) {
        String requestId = request.getHeader("X-Request-ID");
        if (requestId == null || requestId.isEmpty()) {
            requestId = "req-" + UUID.randomUUID().toString();
        }
        return requestId;
    }
}
```

## 8. Endpoint Contract Integration

`SDD/Adapters/Api-rest-endpoints.md` is the source of truth for endpoint methods, paths, request/response DTOs and expected HTTP statuses.

Each endpoint must document or be traceable to its primary error cases. The implementation must verify that:

1. Every documented endpoint reaches the global handler on failure.
2. Status codes match both the endpoint contract and this classification.
3. Authentication and authorization failures are not converted to generic `400` errors.
4. Persistence failures are not exposed as raw database errors.
5. Successful responses are not changed into error responses after headers are sent.

---

## 9. Required Tests

At minimum, provide tests for:

- **Malformed JSON and invalid DTO** → `400 INVALID_REQUEST`
- **Invalid domain value** → `400 INVALID_DOMAIN_VALUE` or `422 INVALID_DOMAIN_VALUE`
- **Invalid credentials and missing token** → `401 AUTHENTICATION_REQUIRED`
- **Forbidden role or operation** → `403 FORBIDDEN`
- **Not-found exception** → `404 RESOURCE_NOT_FOUND`
- **Duplicate/conflict exception** → `409 RESOURCE_ALREADY_EXISTS`
- **Persistence/dependency failure** → `503 DEPENDENCY_UNAVAILABLE`
- **Unexpected exception** → `500 INTERNAL_ERROR`
- **Stable response shape and error code**
- **Request ID propagation** across logs and response
- **No duplicate response** when headers were already sent
- **Every documented endpoint's principal error cases**

**Example Test (Jest / TypeScript):**

```typescript
describe('GlobalExceptionHandler', () => {
  it('should return 400 for malformed JSON', async () => {
    const response = await request(app)
      .post('/api/v1/auth/login')
      .send('{ invalid json }')
      .expect(400);

    expect(response.body.code).toBe('MALFORMED_JSON');
    expect(response.body.status).toBe(400);
    expect(response.body.requestId).toBeDefined();
  });

  it('should return 401 for missing authentication', async () => {
    const response = await request(app)
      .get('/api/v1/buyer/profile')
      .expect(401);

    expect(response.body.code).toBe('AUTHENTICATION_REQUIRED');
    expect(response.body.status).toBe(401);
  });

  it('should return 404 for not found product', async () => {
    const response = await request(app)
      .get('/api/v1/catalog/products/prod-999')
      .expect(404);

    expect(response.body.code).toBe('RESOURCE_NOT_FOUND');
    expect(response.body.status).toBe(404);
  });

  it('should return 409 for duplicate email registration', async () => {
    // First registration
    await request(app)
      .post('/api/v1/auth/register/buyer')
      .send({
        email: 'test@example.com',
        password: 'SecurePass123!',
        firstName: 'John',
        lastName: 'Doe',
      });

    // Second registration with same email
    const response = await request(app)
      .post('/api/v1/auth/register/buyer')
      .send({
        email: 'test@example.com',
        password: 'AnotherPass456!',
        firstName: 'Jane',
        lastName: 'Doe',

      .expect(409);
```

## 10. Acceptance Gate

The Global Exception Handler is `VERIFIED` only when:

1. This contract is implemented for the detected stack (Express, NestJS, or Spring Boot).
2. The handler is registered globally after routes or through the framework equivalent.
3. All exception categories have deterministic mappings.
4. Unknown errors return `500` without internal details.
5. Tests pass for all required categories.
6. Endpoint documentation and implementation agree on status codes.
7. Build, unit tests and integration/REST tests pass with recorded commands and exit codes.

Until all conditions pass, the deliverable must be marked `PARTIAL` or `FAILING`, never `VERIFIED` or `COMPLETE`.
